# 轻阅 · 音色包朗读开发计划

> 依据：[`voice-tts-design.md`](./voice-tts-design.md) Rev 2（2026-10-24）
> 人员：1 人。日历大约 7 周。阶段 3 若权重许可不能商用，就停在阶段 2，不空等。账号方案已定，见设计稿第 7.1 节。
> 状态：计划，未开工。

---

## 1. 排期原则

1. 先让桌面端离线读出声，再做付费建档。建档服务不做逐句合成。
2. ZipVoice int8 那份约 104 MB 的权重，加上声码器，只在用户确认后下载到应用数据目录。不进仓库、不进 `public/`、不进 `dist/`、不进 Tauri `bundle.resources`、不进鸿蒙 `rawfile/qy`。
3. 阶段 1 只打通 macOS 桌面。Android、iOS、鸿蒙、PWA 在阶段 4 接同一套引擎包。这些端在阶段 1 可以看见「朗读」，但点下去只说明尚未支持，并且不发起下载。
4. 播放和下载先用假实现测状态机，最后再接真正的 sherpa。这样分句、高亮、确认后才下载，不依赖 104 MB 文件就能单测。
5. 每一阶段结束跑同一组检查，见第 7 节。

## 4. 阶段 1 · 桌面内置音色（第 2–3 周）

目标对应 AC-001、AC-002、AC-003、AC-004、AC-005、AC-009。

建议顺序不能颠倒：先纯函数和状态机，再下载，最后才接真实推理。

### 第 2 周 · 不碰模型也能测

| 编号 | 工作 | 落点 | 完成时 |
|---|---|---|---|
| 1.1 | 分句 | `src/core/text/sentences.ts`，`tests/unit/sentences.test.ts` | `pnpm test` 通过 AC-009 的夹具：句号、问号、叹号、省略号、破折号、中英文引号、小数点、英文缩写 |
| 1.2 | 朗读状态机 | `src/tts/player.ts` | 单测：给 3 句假音频，状态按「当前句 → 下一句」前进；暂停停在当前句；停止回到空闲。不打开扬声器 |
| 1.3 | 引擎状态 | `src/tts/types.ts`、`src/tts/engineStore.ts`、`src/tts/manifest.ts` | 状态只有 `absent / downloading / verifying / installed / failed`。`manifest.ts` 只放版本、URL、字节数、sha256，模块加载时不发请求 |
| 1.4 | 下载器 | `src/tts/download.ts` | 单测用假的 `fetch`：确认前调用次数为 0；取消后不是 `installed`；字节被截断或 sha256 错误时删除 `.part` 并回到 `absent`（AC-003、AC-005） |
| 1.5 | 阅读页入口 | `src/features/reader/ReaderPage.tsx` 底部 `reader-tools` 增加朗读按钮；`ReadAloud.tsx` 用 `import()` 加载 | 未点击时网络面板无朗读请求。点击后先出现体积说明，不立刻下载 |

`ReaderPage.tsx` 只加按钮和挂载点，不把下载、推理写进这个文件。

### 第 3 周 · 接上真实引擎

| 编号 | 工作 | 落点 | 完成时 |
|---|---|---|---|
| 1.6 | 存放 | 按 0.5 的结论，macOS 写到应用数据目录 `tts/engine/<version>/` | 安装包体积不因此增加。权重不进 IndexedDB |
| 1.7 | 桌面推理 | Tauri 增加一条命令：从应用数据目录里已下载的 sherpa 可执行文件或动态库朗读一句，返回 wav。sherpa 本身属于引擎包，不写进 `Cargo.toml` 的默认依赖 | 命令只在引擎状态为 `installed` 时可用 |
| 1.8 | 播放 | `src/tts/runtime.ts`、`src/tts/player.ts` 接 Web Audio。播第 N 句时预合成第 N+1 句。当前句加标记并滚进视野 | 内置音色断网连续朗读 10 分钟；期间能翻页、加书签（AC-004） |
| 1.9 | 包体检查 | `scripts/check-tts-package.mjs`，接到 `pnpm build` 之后手工跑 | `dist/` 中搜不到 `encoder.int8.onnx`、`vocos_24khz.onnx`、`espeak-ng-data`。主包 gzip 仍 < 180 KB（AC-002） |
| 1.10 | 设置 | `SettingsPage.tsx` 的 `SECTIONS` 增加「朗读」：查看引擎状态、删除引擎 | 删除后状态回到 `absent`，书籍还在。再次朗读会重新走确认下载 |

其他系统上的按钮在这一阶段显示「朗读即将支持」，点击不调用 `download.ts`。

## 6. 阶段 3 · 账号与建档（第 5–6 周）

开始条件：0.4 的结论是「能商用收费」。做不到就停在阶段 2。用户仍可使用内置音色，以及自己导入的音色包。

账号按设计稿第 7.1 节，对照 nebulasforce 的登录和口令哈希，不搬组织、权限和单点登录。服务端放在 `services/voice-enroll/`（Python / FastAPI），不塞进 Tauri 进程，也不走 `src/sync/`。

第 5 周先做账号，第 6 周再把建档接到账号上。

### 第 5 周 · 账号

| 编号 | 工作 | 完成时 |
|---|---|---|
| 3.1 | SQLite：`accounts`、`refresh_tokens`。启动时缺少 `JWT_SECRET` 则进程退出 | 单测不依赖外网。库文件不进 git |
| 3.2 | `POST /v1/auth/register`、`/login`、`/refresh`、`/logout`，`GET /v1/auth/me` | 注册和登录返回同样的令牌对。用户名重复返回 409 风格的业务码。口令短于 8 位拒绝 |
| 3.3 | 口令：服务端 6 位盐 + bcrypt。错误口令与不存在的用户名同一句提示。连续 5 次失败锁定 15 分钟 | 单测覆盖这三件事。响应和日志里没有哈希和盐 |
| 3.4 | 刷新令牌存 SQLite，刷新时删旧发新，退出后旧令牌不能再刷新 | 单测：退出后再刷新得到未登录 |
| 3.5 | 客户端设置区：注册、登录、退出。刷新令牌进 IndexedDB，访问令牌只留内存。未打开该区时不请求 `/v1/auth/*` | 断网阅读不受影响。登录失败不弹阻断阅读的窗 |
| 3.6 | `POST /v1/admin/credits`，口令来自环境变量 `ENROLL_ADMIN_TOKEN`。未配置则路由不存在 | 给测试用户加上次数后，`/auth/me` 的 `enrollCredits` 增加。错误口令拒绝 |

信封与 nebulasforce 一致：`success`、`code`、`message`、`data`。

### 第 6 周 · 建档接到账号

| 编号 | 工作 | 完成时 |
|---|---|---|
| 3.7 | `GET /v1/health`、`POST /v1/voices/enroll`、`GET /v1/voices`、`DELETE /v1/voices/:id` | 路由表里没有 `tts/stream` 和 `tts/synth`。无访问令牌时建档和列表返回未登录 |
| 3.8 | 建档流水：去静音、去噪、24 kHz 单声道、单人检测、切 5–15 秒、写出对齐文本、打分 | 太短、太吵、像多人时返回对应原因，不返回半成品包，不扣次数 |
| 3.9 | 次数为 0 时不接收音频。成功后次数减 1，并删除原始上传。音色包带 `account_id` | 测试里上传文件在成功响应之后从临时目录消失 |
| 3.10 | 客户端试读：固定引导文、5–15 秒、可回放可重录。整段录音就是对齐文本，因此不切更长的片段。授权未勾选时提交函数不被调用（AC-008） | 麦克风权限只在进入试读时申请。未登录时提交按钮不可用 |
| 3.11 | 上传备路径，复用字体导入那类文件选择 | 失败原因显示在建档区，不弹阻断阅读的窗 |
| 3.12 | 返回的包写入 `voices`，立刻可以本机朗读 | 断网后这条音色仍在 |
| 3.13 | 第二台设备登录后 `GET /v1/voices` 只返回该账号的包 | 下载的是 wav + 文本，不是模型。用另一个账号删这个 id，得到找不到 |
| 3.14 | 建档域名无法解析 | 阅读、已安装引擎、已有音色都还在（AC-007） |

建档按次数计费，次数就是 `enroll_credits`。朗读时长不计费。支付渠道不在这 7 周里。

### 用户中心

账号仍只属于建档服务，不进入书架和阅读。设置里增加「账号」，点开才加载这一段。主包不包含注册表单和账号客户端。

| 编号 | 工作 | 完成时 |
|---|---|---|
| 3.15 | 设置导航「账号」，懒加载 | 未点开时不请求 `/v1/auth/*`。阅读页没有账号入口 |
| 3.16 | 注册、登录、退出，以及当前用户名和建档次数 | 注册成功即处于登录状态。退出后刷新令牌不能再用 |
| 3.17 | `POST /v1/auth/password`。成功后作废该账号全部刷新令牌，并签发新的一对 | 旧口令不能登录。旧刷新令牌不能刷新。原口令错误不扣建档次数 |
| 3.18 | 朗读区不再放注册表单。建档沿用账号区的同一会话 | 打开朗读时，本地没有刷新令牌就不请求服务器 |
| 3.19 | 服务地址由用户填写。更换地址时清掉本机会话，不访问旧地址 | 断网仍可阅读、使用已导入的音色 |

不做头像、昵称、邮箱、支付，也不在书架上显示登录状态。

## 8. 每阶段都要跑的检查

```bash
pnpm test
pnpm typecheck
pnpm build
```

然后在 `dist/`、桌面产物里搜索 `encoder.int8.onnx`、`vocos_24khz.onnx`、`espeak-ng-data`，结果应为空。

断网打开一本已导入的书：翻页、书签可用。若本阶段还没有点过朗读，网络面板里也不该出现引擎 CDN。

## 9. 停手条件

| 情况 | 做法 |
|---|---|
| 0.4 许可不能商用 | 停掉阶段 3。阶段 1 和 2 可以交付：内置音色 + 自己导入音色包 |
| 0.2 手机实时率接不上 | 手机不做克隆。桌面计划不变。手机若内置音色也接不上，阶段 4 只保留下载说明，不承诺跟读 |
| 0.5 沙箱放不下 100 MB | 换应用数据目录。仍然禁止放进安装包和 IndexedDB |
| 建档服务被做成逐句合成 | 停。这会让免费朗读重新占用服务器 |

阶段 5 不在本计划内：高保真加工仍要返回客户端音色包，不能新增按句合成接口。
